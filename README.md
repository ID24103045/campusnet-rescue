# CampusNet Rescue - CTF Play Box (IE3132 Assignment 02)

Group 38 - IT24103045, IT24102161, IT24101451, IT24102239.
Six chained stages (OSINT, steganography, cryptography, web, forensics, networking/Linux) served through CTFd.
Everything is fictional and runs only inside an isolated lab VM.

## 1. Layout

| Path | What | Owner |
|---|---|---|

| `challenges/cnr-01..03`, `solvers/m2_*` | Stage 1-3 builders and solver | Member 2 |

## 2. Requirements

Ubuntu 22.04/24.04 VM (4 vCPU, 8 GB RAM, 40 GB disk recommended) on a **host-only / private network**,
Docker Engine + Compose v2, `python3` with `requests`, `curl`, `openssl`, `iptables` (sudo).
For rebuilding artefacts and running solvers/tests: `pip install scapy pillow reportlab flask requests paramiko pypdf`, `apt install steghide libimage-exiftool-perl zip`.

## 3. Deploy from scratch

```bash
cp .env.example .env            # set LAB_BIND_IP to the VM's host-only address, change all passwords
./scripts/deploy.sh             # secrets+cert -> manifest check -> build -> up -> CTFd import -> firewall -> health check
```

Participants: `https://<LAB_BIND_IP>/` (register; challenges unlock in order), portal `http://<LAB_BIND_IP>:8081`, service `<LAB_BIND_IP>:2222`.
If the automatic CTFd setup wizard fails (CTFd version differences), finish the wizard in the browser, create an admin API token
and run `CTFD_TOKEN=<token> python3 platform/ctfd/setup_ctfd.py --base https://<host> --insecure`.

To rebuild artefacts from source: `./scripts/build_all.sh` (regenerates `dist/`, `manifests/SHA256SUMS`, `master/`).

## 4. Reset / recovery

| Command | Effect |
|---|---|
| `./scripts/reset.sh files` | verify `dist/` against the manifest, restore from read-only `master/` if tampered |
| `./scripts/reset.sh stage4` | recreate the portal container (its DB is a tmpfs, so state is wiped; new session key) |
| `./scripts/reset.sh stage6` | recreate the SSH container (flag re-written from Docker secret, permissions reset) |
| `./scripts/reset.sh challenges` | all of the above |
| `./scripts/reset.sh ctfd` | wipe the CTFd DB/uploads volumes only and re-import the six challenges |
| `./scripts/reset.sh all` | everything |

## 5. Checks and tests

```bash
./scripts/health_check.sh                 # services up, DB not published, manifest ok
sudo ./scripts/isolation.sh status        # host firewall rules
./scripts/isolation_test.sh               # egress/peer/DB blocked, no docker.sock, caps/user/readonly
./scripts/resources.sh                    # CPU/memory/pids usage and limits
python3 tests/m4_e2e_test.py --stage4 http://$LAB:8081 --ssh $LAB:2222 [--ctfd https://$LAB --token T]
```
Reports are written to `tests/logs/`. Solvers (`solvers/`) are the official solution paths used by the tests.

## 6. Security controls (summary)

Separate `control_net` (10.40.0.0/24) and `challenge_net` (10.50.0.0/24); challenge network has NAT disabled and DOCKER-USER rules drop
challenge->control and challenge->outside traffic; MariaDB/Redis have no published ports; challenge containers have all capabilities dropped
(stage 6 keeps only the five sshd needs), `no-new-privileges`, memory/CPU/PID limits, read-only root filesystem, no Docker socket, no host mounts;
flags for stages 4 and 6 are Docker secrets (not in image layers or environment); Nginx rate-limits flag attempts; logs are rotated.
